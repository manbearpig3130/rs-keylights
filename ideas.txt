Your tuning, and what it means for the library. With the guitar in E standard plus the Drop pedal, a song's tuning tells the page exactly what you'd need:

Standard tunings below E (Eb, D, C#, C, B…) are just a pedal setting.
Drop tunings (Drop D, Drop C…) also need the low string retuned.
So the library filter becomes "playable with just the pedal" versus "needs a retune". When a song loads, the Launchkey and page could also say "Drop −5", so you set the pedal and never touch Rocksmith's tuner. (S)

The piano roll: it's a scrolling view of the keyboard's notes as bars: pitch going up, time going sideways, with each bar's length showing how long to hold the note. The Casio's lights only show now, so the roll would add look-ahead and durations. Since you already have the Casio, it's low value on its own. It would make more sense as one lane of the tab peek-ahead than as its own feature.

.feedpak: an open format is good news.

On the page and the keys: rs-keylights could read the charts directly, for the fretboard, the tab peek-ahead, the Casio and the Launchkey. Straightforward. (M)
In Rocksmith itself: converting the charts to Rocksmith's format is doable now that we know it well. The audio is the hard part: Rocksmith only plays its own audio format (Wwise). The fun workaround is a mod that plays the feedpak's audio itself, kept in step with the game's clock. (XL)
Your audio input idea: yes, and it's a good one.

Why it should work: RS Re-ARMed already has a hook on the game opening its guitar input (si_open), and RS Re-ARMed's own Mac audio layer is code we control.
What you'd get: pick "TC Helicon Blender, input 1" once, with no aggregate device, BlackHole or LadioCast running.
The less obvious benefit: BlackHole and LadioCast each add buffering, so cutting them out should lower latency, and lower latency means tighter timing feedback when you play. rs-keylights' guitar listening would read the Blender directly too.
